## 2. `LLM_FORCE_DOWN=1` — единый статус и сохранённые тексты (AC02)

Поднять API и воркеры с `LLM_FORCE_DOWN=1`.

- [ ] `GET /health` → `llm_status=down`, `status` по-прежнему отражает
      хранилища (LLM не делает сервис `degraded` сам по себе).
- [ ] `POST /chat/{kind}/messages` → `503`, код ошибки `llm_unavailable`,
      SSE не открыт.
- [ ] Уже готовый текст темы: `status=ready`, `mark=saved_version`,
      `reason=llm_unavailable`, **текст тот же самый**.
- [ ] Текста нет вовсе: `text=null`, `reason=llm_unavailable`,
      `status` ≠ `ready`. Заглушки нет.
- [ ] Оценка ответа на задачу, порядок сетов и прогноз не изменились —
      сверить с записью из п.1.
- [ ] `select status, dependency, attempts from job_outbox where ...` →
      `waiting_dependency`, `llm`, **`attempts = 0`**.

- [ ] После снятия флага задача всё равно выполнилась.

## 4. Классы ошибок провайдера

Проверяется тем, что реально удалось воспроизвести; невоспроизведённое
помечается «не воспроизводилось», а не «работает».

| Класс | Ожидание | Наблюдалось |
|---|---|---|
| timeout | defer, breaker, ожидание; чат — `StreamError` | |
| 429 | defer 30 с (или `Retry-After` в пределах договора), не глобальный down | |
| 5xx | breaker, `waiting_dependency`, defer 120 с | |
| невалидный structured output | один встроенный retry, затем `failed` с `invalid_output` — **не** парковка как авария | |
| провал постпроверки | текст не публикуется, одна перегенерация, затем `failed` | |
