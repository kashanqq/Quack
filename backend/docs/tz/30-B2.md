## 1\. Что ты делаешь в этой фазе

Ты строишь слой, через который всё приложение говорит с языковой моделью, — и выбираешь саму модель. Клиент с двумя слотами моделей, таймаутами, circuit breaker, rate-limit и structured output; реестр инструментов, из которого генерируется JSON Schema для `tools`; общий цикл «модель → вызов инструмента → результат → модель», отдающий типизированные события потока; загрузчик промптов с версиями; фейковый клиент для тестов всей команды. Плюс эхо-режим чата: авторизованный пользователь отправляет сообщение и получает потоковый ответ модели через транспорт B3. Агенты подбора и репетитора в этой фазе — только сигнатуры и списки инструментов, наблюдатель — только схема выхода. В конце фазы `tests/llm` зелёные с фейком, чек-лист на живом провайдере пройден, провайдер записан в `docs/decisions/llm-provider.md`.

Твои зоны: `app/llm/`, `app/agents/`, `tests/{llm,agents}/`, `docs/decisions/llm-provider.md`, `docs/tz/checklists/phase1-B2.md`. В `deploy/.env.example` — только значения переменных `LLM_*` и `MODEL_*` (через sync-log или одной строкой B3 в чате).

Что ты не делаешь: логику ассистента подбора и репетитора (кроме эха), наблюдателя, извлечение программ, генерацию текстов, сборку контекста (это `graph.context` у B1), SSE-транспорт и запись событий (B3), инструменты, которые что-то читают из БД (в Ф1 их тела — стабы).

## 3\. Клиент — `app/llm/client.py`

### 3.1 Интерфейс

class LLMClient:

    def \_\_init\_\_(self, settings: Settings, redis: Redis): ...

    async def complete(self, messages: list\[LLMMessage\], slot: ModelSlot,

                       tools: list\[dict\] | None \= None, temperature: float | None \= None,

                       response\_format: dict | None \= None) \-\> LLMResult

    async def stream(self, messages: list\[LLMMessage\], slot: ModelSlot,

                     tools: list\[dict\] | None \= None) \-\> AsyncIterator\[StreamEvent\]

    async def structured(self, messages: list\[LLMMessage\], schema: type\[T\], slot: ModelSlot) \-\> T

    async def status(self) \-\> LLMStatus

`FakeLLMClient` (§3.6) реализует тот же интерфейс; весь код приложения зависит от интерфейса, не от класса — объяви `Protocol LLMLike` в `client.py`.

### 3.2 Транспорт

`openai.AsyncOpenAI(base_url=settings.llm_base_url, api_key=settings.llm_api_key, timeout=..., max_retries=0)` — ретраи делаешь сам (см. 3.4), чтобы breaker видел каждую ошибку. Модель по слоту: `settings.model_chat` / `settings.model_bulk`. Таймаут по слоту: `LLM_TIMEOUT_CHAT_S` / `LLM_TIMEOUT_BULK_S`. `complete` → `chat.completions.create(stream=False)`; `stream` → `stream=True`, из чанков собираются `TextDelta` по `delta.content` и `ToolCall` по `delta.tool_calls` (аргументы приходят кусками — накапливать по `index`, отдавать `ToolCall` один раз, когда `finish_reason == "tool_calls"` или чанк закрыт). `usage` — из последнего чанка, если провайдер отдаёт.

### 3.3 Rate-limit

Токен-бакет в Redis на ключ `keys.llm_ratelimit(slot)`: ёмкость `LLM_RPM_<slot>`, пополнение раз в минуту (Lua-скрипт или `INCR` \+ `EXPIRE 60` на скользящее окно — второе допустимо). Перед каждым вызовом: `acquire(slot)`; лимит исчерпан → для `chat` ждать до 5 с и повторить проверку, потом `LLMUnavailable("rate limit")`; для `bulk` ждать до 30 с. Общий бакет для API и воркеров — они читают один Redis (tech-stack §4.1: «чтобы очередь bulk не съела дневной лимит во время живого чата»).

### 3.4 Circuit breaker и статус — tech-stack §4.7

- Ошибки, которые считаются: таймаут, HTTP 5xx, 429, сетевые. Не считаются: 400 (плохой запрос — это баг), невалидный JSON от модели.  
- Счётчик в Redis `quack:llm:errors` (ZSET по времени или INCR с EXPIRE 60). ≥ 3 ошибки за 60 с → `keys.llm_status() = "down"` с TTL 120 с. Пока `down` — любой вызов сразу `LLMUnavailable`, без обращения к сети. По истечении TTL — статус `degraded`, следующий вызов — проба: успех → `ok`, ошибка → снова `down` на 120 с.  
- Первая-вторая ошибка за минуту → `degraded` (без блокировки).  
- `LLM_FORCE_DOWN=1` → `status()` всегда `down`, вызовы бросают `LLMUnavailable`. Это для демо фоллбеков на защите.  
- `status()` читает Redis; нет ключа → `ok`.  
- Ретрай внутри клиента: один повтор через 1 с при таймауте/5xx/429 для `bulk`; для `chat` без повтора (ученик видит ошибку быстрее, чем ждёт вдвое).

### 3.5 Structured output — tech-stack §4.2

`structured(messages, schema, slot)`:

1. `LLM_STRUCTURED_MODE=response_format` → `response_format={"type": "json_schema", "json_schema": {"name": schema.__name__, "schema": schema.model_json_schema(), "strict": True}}`. Провайдер не принимает `strict` → без него (флаг `LLM_STRICT_SCHEMA`, по умолчанию `False`).  
2. `LLM_STRUCTURED_MODE=tool` → `tools=[{"type":"function","function":{"name":"emit","parameters": schema.model_json_schema()}}]`, `tool_choice={"type":"function","function":{"name":"emit"}}`; результат — `args` вызова.  
3. Текст ответа: снять ограждения ```` ```json ... ``` ````, обрезать до первой `{`/последней `}`; `schema.model_validate_json`.  
4. Невалидно → один повтор с добавленным сообщением `user: "Ответ не прошёл валидацию: <ошибка>. Верни только JSON по схеме."`; снова невалидно → `LLMUnavailable("structured output failed")` и лог с обрезанным ответом (200 символов).

### 3.6 Фейк — `app/llm/fake.py`

`class FakeLLMClient: def __init__(self, script: list[FakeTurn] | None = None)`; `script` — очередь ответов, по одному на вызов; `FakeTurn = LLMResult | list[StreamEvent] | Exception | BaseModel`. `complete` возвращает следующий `LLMResult`; `stream` отдаёт события следующего списка; `structured` возвращает следующий `BaseModel` (или строит из `LLMResult.text` через валидацию — чтобы тестировать ретрай невалидного JSON); `Exception` в очереди — бросается. Пустая очередь → `stream` отдаёт `TextDelta("(fake)")`. Записывает все входящие вызовы в `self.calls: list[FakeCall(method, messages, slot, tools)]` — тесты проверяют, что ушло модели. `status()` возвращает `self.forced_status` (по умолчанию `ok`).

## 4\. Инструменты, промпты, цикл

### 4.1 Реестр — `app/llm/tools.py`

@tool(name="get\_exam\_format", description="...")

async def get\_exam\_format(args: GetExamFormatArgs, ctx: ToolCtx) \-\> ExamFormat: ...

- `ToolCtx(student_id, deps: AgentDeps, request_id)` — что получает каждый инструмент.  
- Декоратор `tool(name, description)` проверяет, что у функции ровно два параметра, первый аннотирован `BaseModel`; сохраняет `ToolSpec(name, description, args_model, fn, read_only: bool = True)`.  
- `class ToolRegistry`: `register(spec)` (дубль имени → `ValueError`), `schemas() -> list[dict]` (OpenAI-формат `{"type":"function","function":{name, description, parameters: args_model.model_json_schema()}}`), `call(name, args: dict, ctx) -> Any` — неизвестное имя → `KeyError`; `args_model.model_validate(args)` → `ValidationFailed`; результат сериализуется `model_dump()` если Pydantic; `names()`.  
- Правило репетитора (tech-stack §4.3): реестр, созданный с `read_only=True`, отказывается регистрировать `ToolSpec` с `read_only=False` (`ValueError`). `TUTOR_TOOLS = ToolRegistry(read_only=True)`.

### 4.2 Промпты — `app/llm/prompts.py`

`load_prompt(name: str) -> Prompt(name, version: int, text: str)` — ищет `app/agents/prompts/<name>_v<N>.md`, берёт максимальный `N`; нет файла → `FileNotFoundError`. `Prompt.render(**vars)` — подстановка `{{var}}`; незаменённая переменная → `KeyError` (лучше упасть, чем отправить модели шаблон). `extractor_version` для событий наблюдателя — `f"{name}_v{version}"`.

### 4.3 Цикл инструментов — `app/llm/loop.py`

async def run\_tool\_loop(client: LLMLike, registry: ToolRegistry, messages: list\[LLMMessage\],

                        slot: ModelSlot, ctx: ToolCtx, max\_steps: int \= 6\) \-\> AsyncIterator\[StreamEvent\]

1. `client.stream(messages, slot, tools=registry.schemas() or None)`; `TextDelta` — наружу как есть; `ToolCall` — наружу и в список шага.  
2. После завершения потока, если были вызовы: для каждого — `registry.call` (ошибка → `ToolResult(error=str(e))`, цикл не прерывается); наружу `ToolResult`; в `messages` — `assistant` с `tool_calls` и по `LLMMessage(role="tool", tool_call_id, content=json)` на каждый результат; следующий шаг.  
3. Нет вызовов → конец, отдать `LoopDone(text_full, tool_results, steps)` — внутренний объект, не `StreamEvent`; вызывающий агент сам формирует `Done`. Сделай это через `yield`\-протокол: последний элемент — `LoopEnd` (объяви в `loop.py`, не в `schemas/`).  
4. `steps > max_steps` → `StreamError(code="tool_loop_limit")` и конец.  
5. `LLMUnavailable` из клиента → `StreamError(code="llm_unavailable")`.

### 4.4 Постпроверка — `app/agents/postcheck.py` (product-logic §6.2, tech-stack §4.3)

`check_facts(text: str, tool_results: list[ToolResult]) -> PostcheckResult(ok: bool, mismatches: list[str])`:

- Из `text` извлечь числа (целые и десятичные, с пробелами-разделителями тысяч `1 500`, валютные `1 500 CHF`, проценты) и даты (`12 мая 2027`, `12.05.2027`, `2027-05-12`, `15 декабря`); из `tool_results` — рекурсивно все числовые и датовые значения, даты нормализовать к `date`.  
- Число из текста есть в результатах (с точностью до форматирования) → ок; нет → в `mismatches`. Годы 2024–2030 как отдельные числа не считаются (иначе «в 2027 году» ложно срабатывает). Даты без года сопоставляются по дню-месяцу.  
- Пустой `tool_results` и есть числа → `ok=False` (ассистент назвал число, не вызвав инструмент). Текст без чисел и дат → `ok=True`. В цепочку ассистента ставится в Ф2; здесь — функция и тесты.
