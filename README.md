# Quack!

Сервис для школьников 10–11 класса Казахстана: подбирает программы вузов под конкретного ученика и ведёт подготовку к экзаменам. Ассистент понимает ученика из разговора, собирает профиль, предлагает программы с оценкой реалистичности и строит маршрут подготовки.

> Статус: прототип. Фронтенд — рабочий интерфейс с имитацией ассистента и демо-данными программ. Бэкенд разрабатывается поэтапно в `backend/`.

## Структура репозитория

```
.
├── frontend/          Next.js-приложение (интерфейс)
├── backend/           FastAPI-приложение, миграции и тесты
├── deploy/            Локальная инфраструктура
├── product-logic.md   Продуктовая логика: что делает сервис и по каким правилам
├── arch-logic.md      Техническая архитектура по слоям
├── DESIGN.md          Цели, палитра, ключевые экраны
└── CLAUDE.md          Инструкции для Claude Code
```

Фронтенд и бэкенд живут в отдельных папках со своими зависимостями, настройками и README, чтобы над ними могли независимо работать разные люди:

- всё, что касается интерфейса, меняется только в `frontend/`;
- код API и серверные тесты находятся в `backend/`, локальная инфраструктура — в `deploy/`;
- общие документы (`product-logic.md`, `arch-logic.md`, `DESIGN.md`) лежат в корне, их правки лучше обсуждать с обеими сторонами.

## Быстрый старт

### Фронтенд

Нужен Node.js 20+.

```bash
cd frontend
npm install
npm run dev
```

Приложение откроется на http://localhost:3000. Подробности — в [frontend/README.md](frontend/README.md).

### Бэкенд

Инструкции по запуску — в [backend/README.md](backend/README.md). Локальную инфраструктуру можно поднять командой `make up`, API — `make api`.

## Запуск с нуля на чистой машине

```bash
git clone <repo> && cd Quack
make up                                  # PostgreSQL 16, Neo4j 5, Redis 7
cd backend && uv sync --frozen
cp ../deploy/.env.example .env           # заполнить LLM_* и TAVILY_API_KEY
uv run --frozen alembic upgrade head
uv run --frozen python ../scripts/seed.py
cd .. && make api                        # http://127.0.0.1:8000
make worker-interactive                  # в отдельном терминале
make worker-bulk                         # в отдельном терминале
cd frontend && npm install && npm run dev # http://localhost:3000
```

Без ключа модели сервис поднимается и работает в деградированном режиме:
правила, замер, задачи, план и сохранённые программы доступны, чат отвечает
`503 llm_unavailable`, а тексты показываются сохранённые с пометкой.

## Демо

```bash
cd backend
uv run --frozen python ../scripts/seed.py --demo        # два демо-аккаунта
uv run --frozen python ../scripts/seed.py --demo-check  # готовность, только чтение
```

Учётные данные обоих аккаунтов — в [data/demo/manifest.json](data/demo/manifest.json).
Это специально заведённые тестовые аккаунты, не администраторы.

- **Подготовленный** (`demo@quack.kz`) — заполненная анкета, три сохранённые
  программы и настоящий конфликт дедлайнов. Конфликт не записан руками: он
  выводится из дат в `data/programs_floor/programs.json`, и `seed --validate`
  падает, если перестал выводиться.
- **Чистый** (`demo-clean@quack.kz`) — для живого пути: регистрация, замер из
  шести задач (`n_tasks=6` в запросе, глобальный потолок не понижается),
  первая тема.

`--demo` идемпотентен: повторный запуск ничего не дублирует и не сбрасывает.
Сброс чистого аккаунта — отдельная команда `--reset-clean`.

## Источники, ИИ и ограничения

- **Данные о программах и календарях — демонстрационные.** Все записи в
  `data/programs_floor/` и `data/knowledge_base/` помечены `is_demo: true`, их
  `source_url` ведут на `example.invalid`. Стоимости, пороги и дедлайны
  вымышлены и не пригодны для реальных решений о поступлении.
- **Модель не назначает факты.** Числа, даты и требования берутся из
  источников с `checked_at`; постпроверка вырезает любое число, которого нет
  во входных фактах, и текст с выдуманными данными не публикуется вовсе.
- **Оценки знаний — правила, а не модель.** HLR, confidence, реалистичность,
  подборка и темп считаются детерминированно в `app/knowledge`, `app/sets`,
  `app/matching`; модель пишет только через инструмент, событие или правило.
- **Что не обещается:** круглосуточного мониторинга нет; `exactly-once` между
  PostgreSQL, Neo4j и Redis не гарантируется (гарантия — доставка «хотя бы
  один раз» с идемпотентными эффектами); программы с флагом остаются
  исключёнными до ручной перепроверки.

## Эксплуатация

Релиз, поведение при отказах, восстановление и откат — [docs/runbook.md](docs/runbook.md).

Коротко: ответ ученика не теряется ни при одной аварии, кроме PostgreSQL.
Отказ модели, графа, Redis или поиска переводит сервис в честно помеченный
деградированный режим, а отложенная работа лежит в `job_outbox` и
`events.processed_at IS NULL` и доделывается сама после восстановления — без
повторного действия пользователя.

## Как работаем

- Ветка `main` — стабильная. Новую работу ведём в отдельных ветках и вливаем через pull request.
- В названии ветки и PR полезно указывать область: `frontend/...`, `backend/...`, `docs/...`.
- Один PR — одна область. Если изменение затрагивает и фронт, и бэк (например, контракт API), договариваемся о контракте заранее и делаем два PR.
